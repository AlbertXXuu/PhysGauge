# PhysGauge v1.1.2 patch validation

Status: **VALIDATED RELEASE SOURCE**  
Validation date: `2026-08-31` (`Asia/Shanghai`)

## Release meaning

`v1.1.2` is a maintenance patch over software `v1.1.1`. It corrects the Studio header's shared
shell geometry and makes frozen v1 evidence reproduction portable across the supported NumPy
range. Calibration evidence remains immutable `v1.0.0`; R2 remains the separate frozen
`inconclusive-model` research milestone. This patch adds no candidate, metric, threshold, protocol,
model, experiment, dependency, or research conclusion.

## Observed defects and minimal changes

1. The Studio navigation wrapper added `4px` on every side around already-44px tabs. That wrapper,
   rather than the canonical 160px wordmark, determined the fixed header's resolved height. The
   wrapper now has zero padding; the tab targets remain 44px and the locked header shell values are
   otherwise unchanged.
2. Reproducing the frozen v1 bundle with NumPy 1.26–2.2 failed the old blanket
   `rtol=1e-8, atol=1e-10` comparison even though semantic results were unchanged. The verifier now
   compares the newly serialized JSON representation with the frozen JSON representation, permits
   `rtol=1e-6, atol=1e-10` only at explicitly listed continuous-measurement paths, and requires
   exact equality everywhere else. Linux CI additionally exposed a one-ULP glibc/Windows `sin`
   difference in a generated initial velocity; the explicitly named generated position/velocity
   vector components use the same bounded comparison while scalar case parameters, `case_id`, and
   all structure remain exact.

## NumPy compatibility evidence

The investigation used Python 3.11.0, Pillow 12.3.0, one OpenMP/OpenBLAS/MKL thread, and the same
frozen suite in each environment.

| NumPy | v1 reproduction after patch | Records |
| --- | --- | ---: |
| 1.26.4 | PASS | 240 |
| 2.0.2 | PASS | 240 |
| 2.1.3 | PASS | 240 |
| 2.2.6 | PASS | 240 |
| 2.3.3 | PASS | 240 |
| 2.4.6 | PASS | 240 |

The Windows version matrix above is supplemented by Ubuntu CI with Python 3.12 and NumPy 2.5.2.
That job reproduces the same 240 records and covers the platform-specific case-generation boundary.

Across the pre-patch comparison, NumPy 1.26–2.2 had 515 continuous leaves outside the old
tolerance; the fields were `mse`, `psnr`, `ratio_to_random_mse`, `temporal_gradient_mse`, and
`ratio_to_random_temporal_gradient_mse`. The maximum absolute difference was
`1.7215547032378709e-06` in `psnr`. The maximum relative difference for values above `1e-10` was
`5.360911745103335e-07` in `ratio_to_random_mse`. Larger raw relative differences occurred only for
near-zero Pixel Fréchet values whose absolute differences remained below `1e-10`.

Rendered-frame and squared-difference hashes were identical across all six environments. Float32
mean results split between NumPy 1.26–2.2 and 2.3–2.4, while the same means with a float64
accumulator were identical. This is consistent with NumPy 2.3's documented iterator/reduction
changes. The compatibility fix belongs in reproduction comparison: changing accumulation now
would rewrite frozen numeric outputs and is therefore outside this patch.

## Exactness boundary

Tolerance applies only to:

- numeric components of the generated `p1`, `p2`, `v1`, and `v2` case vectors;
- continuous metric fields in individual records;
- continuous fields inside candidate `mean_metrics`;
- measured values inside monotonicity summaries.

The following remain exact, including type where JSON distinguishes it:

- object keys, list lengths, and container structure;
- schema, protocol, case, candidate, family, and expected-violation identity;
- configuration and severity;
- booleans, integers, record/candidate counts, and all other counts;
- `physics_failed`, every `low_sensitivity_*`, and every `exact_miss_*` field;
- summary detection rates, low-sensitivity rates, exact-miss rates, oracle/violation decisions, and
  monotonicity decisions.

Unrecognized future fields are exact by default. Tests show that a one-ULP platform difference and
a `5e-7` relative change in an allowed continuous value pass, a `2e-6` relative change fails, and
any tested decision, count, configuration, identity, type, key-set, or list-length change fails.

## Frozen boundaries

- `docs/evidence/v1.0.0/**` and `docs/evidence/r2/**` are unchanged.
- Metric and protocol calculations are unchanged.
- The dependency range remains `numpy>=1.26,<3` and `pillow>=10,<13`.
- `CITATION.cff`, previous changelog entries, historical releases, and research claims are
  unchanged.
